01 / 核心思路

小而快 > 大而稳

一个 800 star 但一周涨 200 的项目,比一个 10 万 star 但三个月没动的项目更值得你现在动手。所以「早鸟信号」奖励相对增速和小体量,而不是总 star。

02 / 评分构成

四个维度加权

Early = 45×速度 + 20×新鲜度
      + 20×冷门度 + 15×工程信号

速度  = 0.6×周增速/体量 + 0.4×绝对周增
新鲜度= 仓库年龄越轻越高
冷门度= ≤1k star 满分,≥100k 归零
工程信号= commit 频率 + release + fork 比
03 / 防止被骗

刷星是能被看出来的

纯 star 暴涨但 fork/commit 不动、没有 release、issue 冷清的项目,fork/star 比会异常低或异常高,工程信号分会被扣掉。这只是提示,不是判决——最终仍要你自己点进去看代码。

04 / 数据诚实

不假装精确

刚上线的项目只有 1 天快照,任何「周增速」都是推算值。这类数据会被标注为「基线估算」,不参与早鸟排名。随着每日采集,真实增速会逐渐接管——采集越久,这个站点越准。

GitHub 之外的信号源
很多项目在被 star 之前,先在人肉社区里口口相传
